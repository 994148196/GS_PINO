## 4. 解读

1. **混合代价 ~+26–35% 且对称**：DN 桶 0.667 vs 专职 0.492（+36%）、
   SN 桶 1.203 vs 专职 0.953（+26%）。混合模型需在两种映射间共享容量，
   两桶都略退——代价可量化，但远小于外推崩溃（exp009 §3b 的 3–9 个数量级）。
2. **SN 桶绝对误差高于 DN 桶（两种训练一致）**：专职 0.953 vs DN 0.492。
   可能因素：(a) SN 约束自由度少（3 约束对 4 线圈），X 点滑走窗口更宽、
   分离面对参数更敏感；(b) SN 求解 n_iter 40 vs DN 9，freegs 迭代噪声更大。
   探针数据显示 SN isoflux 残差为 0（唯一 X 点+锚点恰闭合），不是残差问题。
3. **几何误差 v2 修复后两桶同健康**（2026-08-17 重评估）：X 点 1–3 cm、
   sep_mean 0.43–0.56 cm、sep 面积 <0.7%、O 点 <0.7 cm。旧版"DN 30.5 cm
   vs SN 3.8 cm"的相反趋势是诊断伪差——MAST 无墙 + 11 线圈 → find_critical
   报告 5–6 个真空假鞍点，旧版贪心配对给 DN 双 X 点配到假点；SN 单 X 点
   无配对歧义。v2 按真值基准配对 + 局部找回 + NaN 诚实报告后，DN/SN 的
   sep_mean 基本一致（0.56 vs 0.43 cm），与 rel L2（SN > DN）呈弱反相关
   （详见 README §5.3 修复记录）。
4. **config 通道的作用方式**：SN 样本 x_coords up=(0,0) 占位恒值 → z-score
   后恒 0；config 1ch（z-score 后 ±1）成为唯一的位形标识。混合模型学到的
   是条件映射 F(ψ|config)，而非物理一致的任意位形映射——外推（exp009
   交叉）证明专职工件不做条件化就崩溃。

## 4b. config 通道反事实测试（2026-08-17，回答"模型是否自推断位形"）

测试时模型确实被喂了**真实 config 标签**（0/1 作为输入通道，见 README §2
与 evaluate_dn_fno 的 use_config 路径）。它是否**依赖**这个标签？翻转
config 通道（DN 喂 z(1)、SN 喂 z(0)）再前向：

| test | 真实 config | config 翻转 | 倍率 |
|---|---|---|---|
| DN (n=500) | 0.667% | **36.2%** | 54× |
| SN (n=500) | 1.203% | **27.2%** | 23× |

→ **模型确实在用显式 config 标签**：给错标志就把预测切到错误位形的
映射（36%/27% ≈ 外推级崩溃，量级介于专职外推 253% 与健康 1% 之间——
up 占位仍提供部分区分信号，但 config 是主导条件）。

注意：config 与 up=(0,0) 占位通道在训练数据中 100% 冗余（SN 的 up 通道
恒值、DN 变化），所以"用了 config"≠"不能自推断"。**消融（exp010，
混合训练无 config 通道）已做**：两桶健康且略优于本实验（DN 0.611 vs
0.667、SN 1.148 vs 1.203）——**模型能自己推断位形，config 通道冗余**；
本实验"用"标签只是冗余信号下模型选了省力的条件捷径。
