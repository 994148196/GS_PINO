# exp010 notes — 混合训练消融（无 config 通道）解读

> 2026-08-17 训练与评估。配套 README.md。动机来自 exp008 的 config 反事实
> 测试（模型依赖显式标签）——回答"它能不能自己推断位形"。

## 1. 方法回顾

- exp008 反事实：测试时翻转 config 通道（DN 喂 z(1)、SN 喂 z(0)）→
  DN 0.667%→36.2%（54×）、SN 1.203%→27.2%（23×）。模型**用了**标签。
- 但 config 与 up=(0,0) 占位 100% 冗余 → "用了"≠"不能不用"。
- exp010：同一数据/规模/N=500，`--input-mode xa` 去掉 `--config-input`，
  13 通道，与 exp009 专职同架构——模型只能靠 up 占位恒值结构区分。

## 2. 结果

| test | exp008 (14ch+config) | exp010 (13ch) | exp009 专职 (13ch) |
|---|---|---|---|
| DN | 0.667% | **0.611%** | 0.492% |
| SN | 1.203% | **1.148%** | 0.953% |
| val | 0.8789% | **0.8327%** | 0.490/0.883 |

exp010 两桶都健康且均略优于 exp008（+config）。find_critical 失败 DN
桶 1/500（可忽略），GS 残差比 0.995/0.977 均正常。

几何指标（v2，2026-08-17 重评估）：DN x_lo/x_up 2.65/2.59 cm、sep_mean
0.55 cm、sep 面积 0.70%、O 点 0.50 cm；SN x_lo 0.94 cm（x_up NaN）、
sep_mean 0.40 cm、sep 面积 0.44%、O 点 0.50 cm。与 exp008/exp009 同健康
量级——去掉 config 通道不影响几何保真（无 config 的混合模型同样配得上
X 点/分离面/O 点）。

## 3. 解读：为什么无 config 反而略好？

1. **占位编码 = 物理自包含的位形信号**：SN 的 up=(0,0) 占位不是随机噪声，
   它编码了"该位形没有上 X 点"这一物理事实。模型需要学会把"up 恒值"
   解释为"单零位形"，这正是用户直觉指向的机制——输入里信息本来完整。
2. **显式标签诱导捷径**：有 config 时，条件映射 F(ψ|config) 是更省力的解
   （up 占位与 config 完全相关，误差可以全部摊到条件分支上）。无 config
   时模型被迫学统一的 G(ψ)，由于输入已可完全区分两类，两种解的表达力
   相同，但统一的解泛化更稳（val 略低、test 两桶略低）。
3. **这解释了反事实结果**：翻转 config 崩溃，是因为模型走了条件捷径、
   把 config 当主导开关；但这条捷径是"可选"的——消融证明去掉后它学会
   了不依赖标签的解。
4. **与专职的差距（0.611 vs 0.492）依旧存在**：混合训练共享容量、位形
   间映射不同（DN 双 X 点 vs SN 单 X 点），专职在单一位形上仍更专精。
   这是混合的固有代价，与 config 通道无关。

## 4. 结论

- **回答用户问题：是的，模型自己能推断位形**（占位结构足够），且自推断
  版本略优于喂标签的版本。
- exp008 的 config 通道设计**冗余**——部署时输入按"存在的 X 点"编码即可，
  无需位形标签（更优雅、物理自包含、少一个通道）。
- 更新后的输入设计建议：data_v5 的 x_coords 4 通道 + 占位编码是自包含的，
  混合训练直接 13ch（exp010 架构）。

## 5. 后续可做

- exp010 架构（13ch 混合）作为 data_v5 的标准配置，N=500 → 2000 扩容验证；
- up 占位 vs 真实"上 X 点缺失"编码的等价性：若未来部署时上 X 点位置未知
  但可能存在（测量误差），占位编码的鲁棒性边界；
- 反事实更细：up 通道部分退化（0 附近噪声）时模型对 SN 的容错。
